# Reproduction Protocol

## 1. Register the source claim

Each study manifest records:

- bibliographic source and stable URL;
- a short paraphrase of the source claim;
- the local hypothesis;
- evidence label;
- in-scope methods and metrics;
- original elements not reproduced.

Claims are paraphrased rather than copied. A URL is evidence of attribution,
not evidence that the local study reproduced the source result.

## 2. Freeze data and configuration

All v0.1 data is synthetic and generated by
`scripts/generate_fixtures.py --seed 42`. Manifests and datasets are committed.
The generator rejects unrecognized seeds for release fixture generation.

Every record has:

- stable identifier;
- `synthetic: true`;
- explicit split where applicable;
- no wall-clock timestamp or local path.

## 3. Separate fitting from evaluation

- Retrieval uses no relevance labels for fitting.
- Temperature and Platt parameters use only the calibration split.
- Calibration metrics use only the test split.
- Workflow policies are fixed before test-task evaluation.

The validator checks split labels and ID uniqueness. These checks are bounded
guards, not proof that all forms of experimental leakage are absent.

## 4. Run all declared baselines

The unified runner executes every declared method using fixed ordering and
seed. A missing method result is a release failure.

## 5. Preserve query/example-level evidence

Aggregate metrics are accompanied by JSONL predictions or decisions so a
reviewer can recompute each result.

## 6. Compare only within scope

The report may say:

- "On this synthetic fixture, temperature scaling lowered ECE."
- "The RRF ranking changed query-level outcomes."
- "The constrained proxy rejected unsafe proposals."

It may not say:

- "DPR was reproduced."
- "Temperature scaling is always best."
- "Multi-agent systems are safer."
- "The original paper result was confirmed."

## 7. Record differences and failure cases

Every study report includes:

- source claim;
- local hypothesis;
- reproduced mechanics;
- non-reproduced elements;
- configuration;
- results;
- query/example-level failures;
- differences from source conditions;
- limitations;
- exact rerun command.

## 8. Determinism audit

Release acceptance requires:

1. regenerate fixtures and schemas;
2. run all studies;
3. render reports;
4. parse every CSV, JSON, and JSONL artifact;
5. repeat generation;
6. compare SHA-256 hashes;
7. install a clean wheel and load packaged schemas.
